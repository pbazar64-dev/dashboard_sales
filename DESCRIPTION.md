# Дашборд воронки продаж — краткое описание

## Назначение и реализованные сценарии

Приложение-дашборд для Битрикс24 на платформе Битрикс24 Вайбкод. Оно открывается внутри портала пунктом левого меню и показывает аналитику по сделкам CRM от имени авторизованного пользователя: каждый сотрудник видит только те сделки, которые доступны ему по правам CRM.

Реализованные сценарии:

1. **Сводка по стадиям воронки.** По каждой стадии (`stageId`) показаны количество сделок и сумма. Стадии идут в порядке воронки, есть строка «Итого» и подсказка с долей стадии.
2. **Ключевые показатели:**
   - сумма открытых сделок (стадии «в работе»);
   - количество выигранных сделок за период;
   - средний чек (сумма выигранных / их количество);
   - конверсия в успех.
3. **Последние сделки.** 20 последних сделок с названием, суммой, стадией, ответственным и датой создания. Клик по названию открывает карточку сделки в Битрикс24.
4. **Фильтры:**
   - период создания сделки: пресеты или произвольный диапазон с проверкой на клиенте и сервере;
   - воронка;
   - «Все / Мои сделки».

Архитектура: Node.js-сервер в роли BFF без внешних зависимостей и интерфейс на HTML/CSS/JS без CDN. Токен сессии пользователя получает только сервер (от шлюза Вайбкода в заголовке `X-Vibe-Authorization`). В браузер токен не попадает. Ключ приложения хранится как секрет в карточке приложения и в репозиторий не входит.

## Запрошенные скоупы

| Скоуп | Обоснование |
|-------|-------------|
| `crm` | Чтение сделок и их агрегатов по стадиям, справочника стадий (порядок, названия, признак успех/провал) и списка воронок. Основной источник данных дашборда |
| `user` | Имена ответственных в списке последних сделок (`/v1/users`). Урезанные `user_basic` и `user_brief` этот раздел не открывают. Без скоупа вместо имени показывается «Сотрудник #ID» |
| `placement` | Публикация приложения в портале и встраивание (левое меню, при желании вкладка в карточке сделки) |

Приложение только читает данные, записи в Битрикс24 нет. Ключ для деплоя (`vibe:infra`) — отдельный ключ разработчика, в приложение он не передаётся.

## Известные ограничения

- Если за период больше 5000 сделок, API агрегации считает суммы по первым 5000. Дашборд в этом случае показывает предупреждение (количество по стадиям при этом точное).
- Суммы в разных валютах не пересчитываются по курсу и показываются отдельно по каждой валюте.
- Период фильтрует по дате создания сделки. «Выигранные за период» — сделки, созданные в периоде и находящиеся на успешной стадии.
- Отчёт строится по одной воронке, выбранной в фильтре.
- Сессия внутри Битрикс24 живёт около 40 минут и продлевается при активности. После простоя приложение нужно заново открыть из меню (ограничение платформы).

## Инструкция для проверяющего

1. В портале Битрикс24 откройте в левом меню пункт **«Дашборд продаж»**.
2. По умолчанию показан текущий месяц основной воронки. Если сделок мало, выберите «Последние 12 месяцев».
3. Проверьте блоки: сводка по стадиям («Итого» равно сумме строк), KPI, последние сделки. Клик по названию сделки открывает её карточку.
4. Проверьте фильтры: смену воронки, «Все / Мои» и «Произвольный…» период. Если указать дату начала позже конца, появится ошибка и запрос не отправится.
5. Без портала интерфейс можно посмотреть на демо-данных: `DEMO_MODE=1 node server.js`, затем открыть http://localhost:3000.

Полная инструкция по развёртыванию, архитектура и меры безопасности описаны в README.md.
